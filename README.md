# Antigravity CLI model provider (antigravity)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

`antigravity` is a Miyu package. Once it is installed, you can use the local Antigravity CLI (`agy`) as a model provider: every model call Miyu makes is handed to `agy`, using the account you are already logged into in `agy` and its subscription quota.

Here `agy` only does the thinking and answering. Tools such as reading files, running commands and editing files are still run by Miyu, so permissions, confirmations and undo work the same as with any other model. All of `agy`'s own tools are turned off except web search (`search_web`) and viewing files (`view_file`).

This package supports Linux and macOS, not Windows. The design and the test records are in [`docs/00-设计.md`](docs/00-设计.md) (in Chinese).

## Before you install

Before you install this package, have these two things ready:

- Install Antigravity CLI 1.4.0 or newer and log in. Run `agy` once in a terminal; if it can hold a normal conversation, you are ready.
- The Miyu core must be 2026.11.0-rc.5 or newer. If the core is too old, this package cannot be installed: the install fails and either asks you to update Miyu first, or reports an unrecognized table `[providers]` in the manifest. If you see either message, upgrade the core first.

## Installing and configuring

Run:

```bash
miyu pkg install antigravity
```

During installation, Miyu asks you to approve the package's two capabilities: providing a model driver, and network access (`agy` needs to connect to Google's services).

After installation, the model provider list has one more entry, `Antigravity` (id `antigravity`), with nothing more to configure by hand. You can choose one of its models with `/model` in a session, for example `antigravity/gemini-3.8-flash-low`, or make it your default model. The model list comes from `agy models`, and the reasoning tier (`low`, `medium`, `high`, `xhigh`) is part of the model name. If you disable or uninstall the package, the provider disappears from the list.

> If you previously added a provider by hand that points to this package (for example `providers.agy`), you can now delete it and use the one that ships with the package instead: `miyu config unset providers.agy.driver`.

### Optional: adjusting individual models

To change a model's context window or reasoning tier, write it in your own configuration file. What you write overrides the defaults the package provides:

```toml
[providers.antigravity.models."gemini-4-hydrogen-high"]
window = 1000000        # agy does not report the context window; fill it in yourself if you want an accurate number
effort = "high"         # recommended for high-tier models; see "Notes on use" for why
```

### About amounts

Miyu recognizes model names such as `gemini-…` and `claude-…`, so it estimates an amount for each turn from the API prices in the model catalog. The amount is only a reference, because what you actually use up is your `agy` subscription quota. If you want the amount shown as 0, run:

```bash
miyu config set providers.antigravity.local true
```

### Settings

You can fill in the settings under `Packages` on the settings page:

| Setting | Key | Default | Description |
|---|---|---|---|
| Executable path | `antigravity.binary` | empty | The full path of `agy`, or of a script that wraps `agy`; a leading `~` means your home directory. If it is empty, the package looks for `agy` on `PATH` |
| Process retention after a turn (seconds) | `antigravity.keep_seconds` | 600 | After a turn ends, the `agy` process is kept this long, waiting for the next turn of the same conversation. 0 means it is not kept |
| Tool call timeout (seconds) | `antigravity.tool_wait_seconds` | 3600 | How long `agy` waits at most after handing a tool call to Miyu. The time Miyu spends running the tool and the time spent waiting for your confirmation both count |

### Optional: using a wrapper script

This package does not choose the account: `agy` uses the home directory Miyu runs with and reads the login from `~/.gemini`.

If you wrap `agy` in your own script (for example, one that spreads work over several accounts), you can point `Executable path` at that script. The script must pass the arguments, standard input and standard output through to `agy` unchanged.

The script can also give `agy` a different home directory, on one condition: `.gemini/config` in the new home directory must be the same folder as the one in your real home directory (for example, through a symbolic link), because the system prompt and the tool server are written there. Whichever home directory `agy` keeps its conversation files in, this package reads and cleans them up in that same directory.

## What it writes into agy's configuration

`agy` only accepts a system prompt and tools through its own configuration files, so this package changes two things under `~/.gemini/config/` and nothing else:

- `agents/miyu-<hash>/agent.md`: Miyu's system prompt. Each prompt uses its own directory, and directories unused for more than an hour are deleted automatically.
- The entry named `miyu` in `mcp_config.json`: this is how `agy` finds this package's tool server. The package only changes this one entry, and the other servers you configured yourself are kept as they are. If the file is not valid JSON, the package does not overwrite it, and that call fails with an error.

As a result, when you run `agy` on its own you will see agents whose names start with `miyu-`. While the Miyu core is running and has used this package, you will also see an MCP server named `miyu`; in an `agy` that Miyu did not start, it offers an empty tool list. When the extension stops normally (the core stops, or the package is disabled or uninstalled), the `miyu` entry is deleted automatically.

`agy` keeps conversation files for each conversation (in `conversations/` and `brain/` under `~/.gemini/antigravity-cli/`). When a conversation ends, this package deletes its conversation files as well.

### Uninstalling

Before you uninstall, it is recommended to clean up the two things above first, and then uninstall:

```bash
miyu antigravity unregister
miyu pkg remove antigravity
```

> The `miyu` entry has already been deleted automatically when the extension stopped normally. `unregister` cleans up the agent directories, and any entry left behind when the extension was killed.

## Notes on use

When you use this package, keep the following points in mind:

- **MCP servers and plugins you configured yourself in `agy` can also be called by the model inside Miyu.** Because `agy`'s MCP configuration is global, this package cannot turn them off. These tools are run by `agy` directly and bypass Miyu's permission checks and confirmations. Miyu faithfully shows every tool that `agy` runs itself and marks it as a "provider-side tool". If you do not want the model to use a server inside Miyu, turn it off in `agy`: `agy mcp disable <name>`.
- **Web search is done by `agy`.** Miyu only shows what was searched and what was found. Reading web page content uses Miyu's own tool.
- **`agy` does not output its thinking, so nothing is output while it thinks.** In testing, when the highest tier (`xhigh`) answered a hard question, it took a minute and a half from sending the request to the first character of output; some models wait one to two minutes on every step. By default Miyu treats 180 seconds without output as a timeout and retries; this package widens the limit to 300 seconds. Setting the matching `effort` for high-tier models is recommended, because the limit then widens further: twice for `high`, three times for `xhigh`.
- **`agy` adds a fixed overhead of about 3,400 tokens of its own to every request**, and this counts against your `agy` quota.
- **Images and files**: `agy` only accepts text, so images and files in a conversation (PDF, audio, video) are first saved as local files, then their paths are given to `agy`, which opens them with its own `view_file`.
- **Warning**: `view_file` can read any file on this computer and is not governed by Miyu's permissions. In sessions where other people take part, such as group chats, other people can also have the AI read files on your computer.
- **Continuing a conversation**: the next turn of a conversation goes to the `agy` process that is still alive, and only the new content is sent. If it cannot continue (for example after the core restarts, after compaction or undo, after switching the model or persona, or when you continue after interrupting a tool), the package starts a new `agy` conversation and sends the full history to it as one block of text. When the history exceeds 170,000 bytes, the oldest content is dropped first.
- **At most 4 `agy` conversations are kept at the same time**, each with its own `agy` process. Beyond that, the one unused for the longest time is stopped.
- **Quota exhausted, rate limits, not logged in, content-policy blocks**: the package classifies these from `agy`'s original error text and reports them to Miyu. Switching model pools and cooldowns are handled by Miyu according to its own rules.

## Troubleshooting

The table below lists common symptoms, their causes and what to do:

| Symptom | Cause and fix |
|---|---|
| `agy (the Antigravity CLI) was not found on PATH` | `agy` cannot be found in Miyu's runtime environment. Fill in `antigravity.binary` in the settings |
| A message saying you are not logged in | Run `agy` once in a terminal and log in |
| `cannot understand …/mcp_config.json` | The file is not valid JSON. Fix it and try again; the package does not overwrite it. Version 0.1.0 also treated the empty file that `agy` creates itself this way; upgrading to a newer version fixes it |
| `agy called a Miyu tool, but its tool server never reached Miyu` | `agy` did not connect to this package's tool server. Run `agy mcp list` and check whether `miyu` exists and whether it has been turned off |
| A tool has already run, but Miyu resends the whole history | `agy` gave up waiting first, or the core restarted. This is normal; that request just uses more quota |

The package's own log is kept at `var/log/antigravity/stderr` in the data directory. It records which tools `agy` ran in each call, and which conversations were discarded and started over.

## Development

During development, run the format check, the lints and the tests:

```bash
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test          # integration tests use a fake agy (tests/fake_agy.py, needs python3) and never call the real agy
```
