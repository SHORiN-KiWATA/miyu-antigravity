# miyu-antigravity

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

[English](README.en.md)

`antigravity` 是 Miyu 的一个软件包。安装之后，你可以把本机的 Antigravity CLI（`agy`）当作一家模型供应商来用：Miyu 的每一次模型调用都会交给 `agy`，使用你在 `agy` 里已经登录的账号和订阅额度。

`agy` 在这里只负责思考和回答。读文件、运行命令、修改文件这些工具仍然由 Miyu 执行，所以权限、确认和撤销都和使用其他模型时一样。`agy` 自带的工具已经全部关闭，只保留了联网搜索（`search_web`）和查看文件（`view_file`）。

这个软件包支持 Linux 和 macOS，不支持 Windows。设计和实测记录可以看：[docs/00-设计.md](docs/00-设计.md)。

## 安装前的准备

- 安装 Antigravity CLI 1.4.0 或更新的版本，并且已经登录。在终端里运行一次 `agy`，如果能正常对话，就说明已经准备好了。
- Miyu 核心需要 2026.11.0-rc.2.6 或更新的版本（0.1.4 起；0.1.3 要 2026.11.0-rc.2.5，0.1.2 要 2026.11.0-rc.2.4）。核心版本太旧时无法安装这个软件包：安装会报错，提示先更新 Miyu，或者提示清单里有不认识的表 `[providers]`。遇到这两种提示，先升级核心即可。

## 安装和配置

运行：

```bash
miyu pkg install antigravity
```

安装时 Miyu 会询问你是否批准这个软件包的两项能力：提供模型驱动，以及联网（`agy` 需要连接 Google 的服务）。

安装完成后，模型供应商列表里会多出一家 `Antigravity`（编号是 `antigravity`），不需要再手动配置。你可以在会话里用 `/model` 选择它的模型，例如 `antigravity/gemini-3.8-flash-low`，也可以把它设置成默认模型。模型列表来自 `agy models`，推理档位（`low`、`medium`、`high`、`xhigh`）包含在模型名里。如果停用或者卸载这个软件包，这家供应商会从列表里消失。

> 如果你之前手动添加过一家指向这个软件包的供应商（例如 `providers.agy`），现在可以删除它，改用软件包自带的这一家：`miyu config unset providers.agy.driver`。

### 可选：调整个别模型

如果想修改某个模型的上下文窗口或者推理档位，可以写在你自己的配置文件里。你写的内容会覆盖软件包提供的默认值：

```toml
[providers.antigravity.models."gemini-4-hydrogen-high"]
window = 1000000        # agy 不会报告上下文窗口，想要准确的数字需要自己填写
effort = "high"         # 推荐给高档位的模型填写，原因见「使用须知」
```

### 关于金额

Miyu 认识 `gemini-…`、`claude-…` 这些模型名，所以会按照模型目录里的 API 价格给每一轮对话估算一个金额。这个金额只是参考，因为你实际消耗的是 `agy` 的订阅额度。如果希望金额显示为 0，可以运行：

```bash
miyu config set providers.antigravity.local true
```

### 设置项

设置项可以在设置页的「软件包」里填写：

| 设置 | 键 | 默认值 | 说明 |
|---|---|---|---|
| 可执行文件路径 | `antigravity.binary` | 空 | `agy` 的完整路径，也可以是包装 `agy` 的脚本；开头的 `~` 表示家目录。没有填写时，软件包会在 `PATH` 里查找 `agy` |
| 对话结束后进程保留时长（秒） | `antigravity.keep_seconds` | 600 | 一轮对话结束后，`agy` 进程会保留这么久，等待同一段对话的下一轮。填 0 表示不保留 |
| 工具调用超时时长（秒） | `antigravity.tool_wait_seconds` | 3600 | `agy` 把一次工具调用交给 Miyu 之后最多等待这么久。Miyu 执行工具的时间和等待你确认的时间都计算在内 |

### 可选：使用包装脚本

这个软件包不负责选择账号：`agy` 使用 Miyu 运行时的家目录，读取 `~/.gemini` 里的登录信息。

如果你用自己的脚本包装了 `agy`（例如按账号分流的脚本），可以把「可执行文件路径」指向这个脚本。脚本需要把参数、标准输入和标准输出原样交给 `agy`。

脚本也可以给 `agy` 换一个家目录，但是需要满足一个条件：新家目录里的 `.gemini/config` 和真实家目录里的是同一份（例如用符号链接指过去），因为系统提示词和工具服务都写在那里。`agy` 的会话文件保存在哪个家目录，这个软件包就会到哪个家目录读取和清理。

## 写入 agy 配置的内容

`agy` 只能通过它自己的配置文件接收系统提示词和工具，所以这个软件包会修改 `~/.gemini/config/` 里的两处内容，不会修改其他内容：

- `agents/miyu-<哈希>/agent.md`：Miyu 的系统提示词。每一份提示词使用一个目录，超过一小时没有使用的目录会被自动删除。
- `mcp_config.json` 里名为 `miyu` 的条目：`agy` 通过它找到这个软件包的工具服务。软件包只修改这一个条目，你自己配置的其他服务会原样保留。如果这个文件不是合法的 JSON，软件包不会覆盖它，这一次调用会报错。

因此，你单独运行 `agy` 时会看到名字以 `miyu-` 开头的代理。在 Miyu 核心运行并且用过这个软件包的时候，你还会看到名为 `miyu` 的 MCP 服务；在不是由 Miyu 启动的 `agy` 里，它提供的工具列表是空的。扩展正常停止（停止核心、停用或者卸载这个软件包）时，会自动删除 `miyu` 这个条目。

`agy` 会给每一段对话保存会话文件（位于 `~/.gemini/antigravity-cli/` 的 `conversations/` 和 `brain/`）。一段对话结束时，这个软件包会一并删除对应的会话文件。

### 卸载

卸载之前建议先清理上面两处内容，然后再卸载：

```bash
miyu antigravity unregister
miyu pkg remove antigravity
```

> `miyu` 这个条目在扩展正常停止时已经自动删除了。`unregister` 负责清理代理目录，以及扩展被强制结束时留下的条目。

## 使用须知

- **你在 `agy` 里自己配置的 MCP 服务和插件，模型在 Miyu 里也可以调用。** 因为 `agy` 的 MCP 配置是全局的，这个软件包无法关闭它们。这些工具由 `agy` 直接执行，不经过 Miyu 的权限检查和确认。Miyu 会如实显示 `agy` 自己执行的每一个工具，标记为「供应商侧工具」。如果不希望模型在 Miyu 里使用某个服务，可以在 `agy` 里关闭它：`agy mcp disable <名字>`。
- **联网搜索由 `agy` 完成。** Miyu 只显示搜索了什么和搜索到了什么。读取网页内容使用的是 Miyu 自己的工具。
- **`agy` 不会输出思考过程，所以思考期间没有任何输出。** 实测最高档位（`xhigh`）回答一道难题时，从发出请求到输出第一个字需要一分半钟；有些模型的每一步都需要等待一到两分钟。Miyu 默认在 180 秒没有输出时判定超时并重试，这个软件包把时限放宽到了 300 秒。推荐给高档位的模型填写对应的 `effort`，因为这样时限会进一步放宽：`high` 是两倍，`xhigh` 是三倍。
- **每次请求 `agy` 自己会附带大约 3,400 token 的固定开销**，这部分计入你的 `agy` 额度。
- **图片和文件**：`agy` 只接收文字，所以对话里的图片和文件（PDF、音频、视频）会先存成本机的文件，再把路径告诉 `agy`，由它用自带的 `view_file` 打开查看。
- **注意**：`view_file` 能读取这台电脑上的任何文件，不受 Miyu 的权限管理。在群聊这类有其他人参与的会话里，别人也可以让 AI 去读取你电脑上的文件。
- **对话的衔接**：同一段对话的下一轮会接在仍然存活的 `agy` 进程上，只发送新增的内容。如果接不上（例如核心重启、压缩、撤销、切换了模型或人格、打断工具之后继续对话），软件包会新开一段 `agy` 对话，并把完整的历史转写成一段文字发送过去。历史超过 17 万字节时，会从最早的内容开始丢弃。
- **最多同时保留 4 段 `agy` 对话**，每段对话对应一个 `agy` 进程。超出时会结束最久没有使用的那一段。
- **额度用尽、限流、没有登录、内容策略拦截**：软件包会根据 `agy` 的报错原文归类，再报告给 Miyu。切换模型池和冷却由 Miyu 按照自己的规则处理。

## 排查问题

| 现象 | 原因和处理 |
|---|---|
| `agy (the Antigravity CLI) was not found on PATH` | Miyu 的运行环境里找不到 `agy`。在设置里填写 `antigravity.binary` 即可 |
| 提示没有登录 | 在终端里运行一次 `agy` 完成登录 |
| `cannot understand …/mcp_config.json` | 这个文件不是合法的 JSON。修复它之后重试，软件包不会覆盖它。0.1.0 版本会把 `agy` 自己创建的空文件也当作这种情况，升级到新版本即可 |
| `agy called a Miyu tool, but its tool server never reached Miyu` | `agy` 没有连接上这个软件包的工具服务。运行 `agy mcp list`，检查 `miyu` 是否存在，以及是否被关闭了 |
| 工具已经执行了，Miyu 却重新发送了整段历史 | `agy` 先判定了超时，或者核心重启过。这是正常现象，只是这一次请求消耗的额度更多 |

软件包自己的日志保存在数据目录的 `var/log/antigravity/stderr`。每一次调用里 `agy` 执行了哪些工具、哪一段对话被作废并重新开始，都记录在这里。
